Este documento contiene toda la información necesaria para que un Agente de IA entienda el estado actual, la arquitectura y los objetivos de este proyecto.

1. OBJETIVO DEL PROYECTO
Se trata de un proyecto académico para la asignatura "Estructura de Datos y Laboratorio" (ITM) dictada por Dennis Arlex Garro Agudelo. Sin embargo, estamos elevando el nivel: no haremos una simple aplicación de consola, sino una **Aplicación Web Profesional (Backend Spring Boot API REST + Frontend Vanilla HTML/CSS/JS)** estructurada bajo **Arquitectura Hexagonal**.

2. REQUISITOS ACADÉMICOS (Lo que pide el profesor - Resumen HUs)
- HU1: Configuración con método main limpio (solo debe iniciar la app/menú).
- HU2/HU3/HU4: Clases Cliente, Vehículo (con herencia a Sedán y SUV) y ContratoRenting demostrando estricta Programación Orientada a Objetos (Encapsulamiento, Herencia, Polimorfismo, Abstracción).
- HU5: Un menú de navegación centralizado.
- HU6: Uso de estructuras dinámicas (Vectores, Pilas y Colas).
- HU7: Generación de informes.
- HU8: Validaciones de datos usando recursividad.

3. NUESTRO ENFOQUE PROFESIONAL (Cómo traducimos lo académico)
- **Consola a Web**: En lugar de bloquear la consola con un menú `Scanner`, el `main` solo inicia Spring Boot. El "Menú" (HU5) es el Frontend Web.
- **Arquitectura Hexagonal**: Separamos el Dominio (reglas puras de POO), la Aplicación (Casos de uso) y la Infraestructura (Controladores Web, BD, Validadores).
- **Pilas y Colas con sentido**: En lugar de usarlas arbitrariamente, usamos una Pila (Stack) para un "Historial de Acciones/Deshacer" y una Cola (Queue) para una "Fila de Espera" de clientes cuando no hay autos.
- **Recursividad real**: Se usan métodos recursivos en las utilidades de validación para limpiar entradas antes de guardarlas.
- En la carpeta `docs/` existe un archivo `HU_MAPPING.md` que justifica ante el profesor cómo cumplimos cada punto en entorno web.
